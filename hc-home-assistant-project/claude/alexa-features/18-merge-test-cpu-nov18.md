## Zima CPU (wake_server.py, stage-2 "Alexa" model)
- **Cause:** onnxruntime's default thread pool spun on all cores: ~445% CPU, Zima load ~9.4. The model itself needs ~3 ms per 80 ms step on one core.
- **Fix 1 (ww.py, used by every ww script):** `intra_op_num_threads = 1`, `inter_op_num_threads = 1`, `session.intra_op.allow_spinning = 0`. Same math, same scores. Backup `ww/backups/ww.py.before-threads-2026-11-18`.
- **Fix 2 (wake_server.py): voice gate like a real Echo.** Model only runs while a step is ≥ 4 dB above the room's quiet level (15th percentile of the last 6 s), plus 1.5 s hangover; the last 0.32 s of gated audio is replayed when sound starts. Lane resets keep their schedule while gated. Constants `GATE_DB/GATE_HANG/GATE_PRE/GATE_HIST` next to the Stream class. Backups `ww/backups/wake_server.py.before-vad-2026-11-18` and `.pre-gate-live`; candidate kept as `wake_server_gated.py`; splice tool `splice.py` + `stream_new.py`.
- **Check (`ww/gate18.py` → `ww/gate18.log`):** all 20 real "Alexa" streams + accept/missed/reject wake-log clips: old and gated peaks identical (0.992–0.996; missed 0.952 = 0.952).
